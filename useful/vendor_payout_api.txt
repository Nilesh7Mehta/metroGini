4) SEND PAYMENT (mark pending batch as paid)
--------------------------------------------------------------------------------
POST /api/admin/vendor-payout/:batchId/pay

Example:
POST /api/admin/vendor-payout/vpb-201/pay

Content-Type: application/json

Body (only these two fields):
  - transaction_id   (required)  e.g. "TXN123456"
  - date             (required)  YYYY-MM-DD  e.g. "2026-07-16"
                                 (alias: payment_date)

Invoice is AUTO-GENERATED when the week closes (status → pending).
No invoice file upload. No invoice_id from admin.

Request example:
{
  "transaction_id": "TXN123456",
  "date": "2026-07-16"
}

--------------------------------------------------------------------------------
STATUS RULES
--------------------------------------------------------------------------------
  today <= date_to   →  invoice_not_generated   (cannot pay; no invoice yet)
  today >  date_to   →  pending                 (invoice auto-generated; can pay any day)
  after pay          →  paid                    (transaction_id + payment_date saved)

GST formula (dummy amounts already include this):
  gst_amount     = ROUND(gross_revenue * 0.18)
  payable_amount = gross_revenue + gst_amount

NOTE:
  Invoice PDFs are written under uploads/vendor-payout-invoices/ when week closes.
  Open via:
    {{API_BASE_URL}}/uploads/vendor-payout-invoices/auto-vpb-201.pdf
    or {{API_BASE_URL}}/api/uploads/vendor-payout-invoices/auto-vpb-201.pdf
  Pay action is in-memory only in Phase 1 (resets when server restarts).
  Week date ranges shift relative to "today", so labels may change day-to-day.
  Real DB / order aggregation comes in Phase 2.
