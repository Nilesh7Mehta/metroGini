METROGINI BACKEND APIs
Two Priority Flows: Create Order + Weight & Payment
Base URL: https://api.metrogini.com

Payment rule (current product): NO advance at booking. Customer pays the FULL bill
only after the laundry weighs the clothes (Razorpay).

================================================================================
FLOW 1 — USER CREATE ORDER
================================================================================
Journey: login → address → services/pricing → pickup slot → create order → finalize
          → assign vendor/rider (no payment)

--------------------------------------------------------------------------------
ASSIGN VENDOR + RIDER AT BOOKING (no payment)
--------------------------------------------------------------------------------
finalize does NOT assign vendor/rider. App uses this next step (₹0):

[EXISTS] POST /api/user/order/payment/:id/pay
Request:
{
  "group_code": "MUM_WEST",
  "shift_id": 1,
  "day_of_week": 2
}
(day_of_week: 1=Monday … 7=Sunday — match pickup_date)

→ assigns vendor_id + assigned_rider_id, reserves slot capacity
→ amount charged: ₹0 (ADVANCE_AMOUNT = 0 in backend)
→ sets payment_status to partially_paid (internal flag only — nothing was paid)

Response:
{
  "message": "Payment successful. Order booked.",
  "order_id": 24571,
  "assigned_vendor": 12,
  "assigned_rider": 5,
  "advance_paid": 0
}

================================================================================
FLOW 2 — WEIGHT CONFIRMATION + FULL PAYMENT
================================================================================
Journey: vendor weighs → bill generated → customer pays FULL amount via Razorpay

--------------------------------------------------------------------------------
VENDOR — CREATE BILL (vendor token)
--------------------------------------------------------------------------------
[EXISTS] POST /api/vendor/order/:order_id/confirm-clothes
Confirm garment count before weight (vendor prerequisite)

[EXISTS] POST /api/vendor/order/:order_id/confirm-weight
Body (form-data):
  actual_weight = 6.8
  is_stained = 0
With stain: is_stained = 1, vendor_request_amount, image files

Sets: actual_weight, final_total, remaining_amount (= final_total − amount_paid),
       GST 18%

[EXISTS] POST /api/vendor/order/:order_id/finalize
→ status order_finalized, user notified "laundry has been weighed"

--------------------------------------------------------------------------------
USER — READ BILL (user token)
--------------------------------------------------------------------------------
[EXISTS] GET /api/user/order/:id/Orderdetail

Use in message:
  actual_weight      → weight in kg
  final_total        → total laundry charges (incl. GST)
  remaining_amount   → full amount to pay (equals final_total when no advance)
  amount_paid        → 0 until Razorpay succeeds
  payment_status     → partially_paid until paid, then paid

--------------------------------------------------------------------------------
USER — PAY FULL AMOUNT (user token)
--------------------------------------------------------------------------------
[EXISTS] POST /api/user/order/payment/:id/create-order
Request:
{
  "amount": 1185.04,
  "payment_type": "remaining"
}
Rule: payment_status must be partially_paid (set at booking via /pay step)
      amount = remaining_amount from Orderdetail (= full bill when amount_paid is 0)

Response:
{
  "key_id": "rzp_...",
  "order_id": "razorpay_order_id",
  "amount": 118504,
  "currency": "INR",
  "payment_type": "remaining"
}

[EXISTS] POST /api/user/order/payment/:id/verify
Request:
{
  "razorpay_order_id": "...",
  "razorpay_payment_id": "...",
  "razorpay_signature": "..."
}

[EXISTS] POST /api/user/order/payment/razorpay/webhook
(Razorpay → MetroGini, server-side)

Note: payment_type is "remaining" in the API even though the customer pays the
full bill — there is no separate "full" type. Legacy "advance" path exists in
code but ADVANCE_AMOUNT = 0 and is not used for booking.

--------------------------------------------------------------------------------
FLOW 2 SEQUENCE (current backend)
--------------------------------------------------------------------------------
Vendor side:
1. POST /api/vendor/order/:order_id/confirm-clothes
2. POST /api/vendor/order/:order_id/confirm-weight
3. POST /api/vendor/order/:order_id/finalize

User / payment side:
4. GET  /api/user/order/:id/Orderdetail          (read bill + remaining_amount)
5. POST /api/user/order/payment/:id/create-order (payment_type: remaining, full amount)
6. POST /api/user/order/payment/:id/verify       (after Razorpay checkout)
